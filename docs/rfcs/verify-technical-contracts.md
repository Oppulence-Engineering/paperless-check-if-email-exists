# Verify audit technical contracts

**Design revision 2 · 2026-10-24 · Proposed, not implemented.**

This companion specifies common contracts for RFCs 0001–0007. Their technical
sections are normative design decisions; examples are proposed interfaces, not
currently callable routes. The separate Go repository still requires a matching
implementation and contract review. Do not represent proposed Go table names as
an inventory of its current schema.

## Identity, storage, and wire types

- Public audit/client/campaign/import/input-row/candidate/operation IDs are random
  UUIDs generated by the owning application. Every tenant-owned table has
  `tenant_id UUID NOT NULL REFERENCES tenants(id)` and composite primary or unique
  key `(tenant_id,id)` for UUID-addressable resources. Join tables, versioned rows
  and period balances use the tenant-prefixed composite keys specified in their RFC.
  Child FKs include `tenant_id`; no unscoped FK or lookup. Platform source-policy
  versions are explicitly global control-plane records; tenant grants reference them.
- Public Go identifiers remain positive decimal strings, never JavaScript numbers.
  Revisions and monetary integers also serialize as decimal strings; Rust parses
  them into bounded integers and rejects overflow. Timestamps are UTC RFC 3339.
- Money uses nonnegative `BIGINT` **USD micro-units** (1 USD = 1,000,000); no float
  math. Internal cost, customer charge, and cash collected are separate fields.
  Multi-currency execution is rejected in v1. Refunds are separate positive
  entries linked to a charge, not negative reservations.
- Mutable resources have `version BIGINT NOT NULL DEFAULT 1 CHECK(version > 0)`.
  Every changed version increments under a row lock. Immutable decisions,
  observations, ledger events, and export manifests append new records.
- `contact_audits.generation` changes when input revisions, target criteria,
  evidence, or decisions change. Export/repair previews bind that generation.
  A tenant `audit_policy_epoch` changes with suppression, negative outcomes,
  sending policies, or source-rights changes. Implement hooks on **all** writers,
  including native provider ingestion and scheduled expiry; time expiry is also
  evaluated directly. Neither counter replaces authoritative eligibility checks.
- Apply SQL migrations additively using the next available repository timestamp.
  DDL in these RFCs is the schema contract; rollout must also add timestamp columns,
  retention indexes, and named constraints described beside each table.

## Authorization matrix

New public scopes are `audits.read`, `audits.write`, `audits.review`,
`audits.export`, `audits.spend`, and `audits.manage`.

| Action | Required scope | Session member | Session owner/admin |
|---|---|---|---|
| List/detail/evidence/progress | read | Yes | Yes |
| Client/campaign metadata, imports, draft repair/CRM previews | write | Yes | Yes |
| Approve/hold/reject contact evidence | review | Yes | Yes |
| Export preview, create/download artifacts | export | Yes | Yes |
| Approve paid plans or recurring spend authorization | spend | No | Yes |
| Retention/deletion, CRM connections/apply, maintenance configuration | manage | No | Yes |

Each operation also needs `audits.read` for its resources. Creating a draft repair
plan requires write; it cannot dispatch. Maintenance paid execution requires both
manage and spend. CRM apply additionally requires export eligibility.

Reject legacy/open-mode contexts and missing/nil tenants before storage access.
For API-key contexts require each exact audit scope; empty lists, `find`, `admin`,
and `*` do not substitute. Owner/admin sessions are recognized through the verified
JWT routing path, not a customer-supplied role. Existing API-plan restrictions
continue to apply. Only an authorized credential manager can grant new scopes;
unknown `audits.*` names are rejected on key create/update. Do not change existing
non-audit endpoint wildcard semantics in the same release.

Rust is the authority for every call. Go validates the server-selected workspace
and original Rust tenant binding. Client/campaign names are organization labels,
not ACL boundaries. Use separate workspaces for clients requiring isolation.

## Request, response, and concurrency conventions

Writes use `Idempotency-Key: <UUID>` and updates to existing resources include
`expected_version` as a decimal string. Missing key/version returns 428; different
body/path for an existing key or a stale version returns 409. Deserializers reject
unknown fields. JSON duplicate member names are rejected before hashing.

Hash SHA-256 over method, normalized resource path, and RFC 8785 canonical JSON.
Use decimal strings for revisions/money/Go IDs; other numeric request fields are
bounded integers within JavaScript's exact range. Preserve array order and reject
unsupported numeric values before canonicalization. File imports hash raw file bytes separately; normalization
never alters the raw source hash. Tenant comes from auth, not the body.

Creation of audit-scoped durable work returns 202 with `Location` and:

```json
{
  "operation_id": "10000000-0000-4000-8000-000000000001",
  "status": "queued",
  "status_url": "/v1/audits/20000000-0000-4000-8000-000000000001/operations/10000000-0000-4000-8000-000000000001",
  "poll_after_ms": 2000
}
```

Audit operations have their own route. Tenant-wide deletion/connection operations
use the status resource specified in their RFC. `/v1/operations/{id}` remains
verification only. A synchronous new resource returns 201; replay returns the saved status/body
and `Idempotent-Replay: true`. Reusing an operation after replay-cache expiry finds
the persistent resource by `(tenant_id,operation_kind,request_key)` before creating
anything. Keep tombstones until the originating authorization expires and all
external effects settle; an expired/deleted operation returns 410, never repurchases.

New errors preserve the existing string `error` and add stable fields:

```json
{
  "error": "The preview no longer matches current evidence.",
  "code": "audit_revision_conflict",
  "request_id": "30000000-0000-4000-8000-000000000001",
  "details": {"expected_version": "4", "current_version": "5"}
}
```

| HTTP | Stable examples | Retry |
|---|---|---|
| 400 / 422 | malformed JSON; invalid mapping; unsupported currency | Correct input; new key for a changed body. |
| 401 / 403 | invalid credentials; missing scope; feature not enabled | Do not loop; refresh auth or change authorized configuration. |
| 404 | missing or other-tenant resource | Same response for both; no existence disclosure. |
| 409 | revision conflict; same key/different request; changed quote | Refresh preview, then make an explicitly new decision. |
| 410 | expired preview; deleted resource | Recreate preview only if resource still permits it. |
| 428 | missing key or expected version | Add required precondition. |
| 429 | rate/quota limit | Honor `Retry-After`; no admission occurred. |
| 503 | DB, budget, required Go capability, or source-policy unavailable | Retry the same key; never assume a timed-out effect did not occur. |

Reads paginate with opaque, HMAC-authenticated cursors binding tenant, audit,
filters, snapshot generation, expiry, and last `(created_at,id)`. Default 50,
maximum 200 rows; no offset scan for new large-run APIs. A live-list generation
change returns 409 `cursor_snapshot_changed`; immutable export/evaluation snapshots
remain pageable. Tokens expire after one hour and contain no raw contact data.

## Durable operations and service boundary

`audit_operations` has `(tenant_id,id)` PK, `audit_id`, kind, request key/hash,
resource version, state, `lease_token UUID`, `lease_until`, attempts,
`next_attempt_at`, result/error references, created/updated timestamps, and unique
`(tenant_id,kind,request_key)`. `audit_dispatch` references it and is inserted in
the **same Rust transaction** as the resource change and admission decision.

Operation states are `queued`, `running`, `waiting_external`, `waiting_review`,
`cancel_requested`, `succeeded`, `failed`, and `cancelled`. Terminal transitions
require all effects to be settled/reconciled; an unknown purchase is
`waiting_external`, not failed-and-forgotten. User cancellation sets
`cancel_requested`; only the owning executor's admission fence and settlement
receipt permit `cancelled`. Retry scheduling changes `next_attempt_at` and lease
metadata without replacing the operation identity. Record append-only
`audit_operation_events(tenant_id,operation_id,sequence,state,reason,occurred_at)`
with a unique tenant/operation/sequence key. Result resources retain their own
feature-specific states, such as export invalidation or a CRM per-item conflict.

Workers claim due rows with `FOR UPDATE SKIP LOCKED`, commit a 60-second lease,
then perform external I/O outside the transaction. Renew every 20 seconds;
updates require the current token. Losing the lease fences local writes but does
not prove an external call was cancelled: reconcile external operation IDs before
redispatch. Poll every two seconds with jitter, maximum four active audit operations
per tenant and sixteen per worker initially. These are configurable initial limits.

Propose `GET /lead-scraper-microservice/api/v1/internal/verifier-contract` using
the existing server credential. Response identifies contract version 1 and enabled
capabilities (`audit_lineage_v1`, `rights_v1`, `claims_v1`, `budgeted_repair_v1`).
Check at startup and before enabling each feature; missing capability returns 503,
not fallback to immediate research. Only the trusted service can call internal
admission/deletion routes. Validate tenant/workspace binding server-side even when
the caller has bootstrap authority. Customer workspace keys cannot mint mappings.

Every cross-service mutation carries a Rust operation UUID, original tenant UUID,
server-resolved workspace, expected version, and contract version. Creation uses
expected version `"0"`; updates require the current positive version. Go persists the
operation ID before work and offers lookup by that ID. A lost response is recovered
by lookup/replay with the same body. The current bridge's no-HTTP-retry policy stays;
the durable operation worker owns reconciliation and bounded backoff.

## Evidence synchronization and validity boundary

Go must expose a monotonic per-audit observation sequence and immutable snapshot
hashes through `GET .../internal/verifier-audits/{audit_id}/evidence-head` and a
cursor-based changes feed. Rust stores the last applied sequence. Apply each change
and increment audit generation in one transaction; duplicate sequence/hash replays,
a different hash conflicts, and a gap marks the projection `refresh_required`.
Missing capability, unknown rights or an unresolved sequence gap blocks new Ready
approval, export publication/download, paid-plan approval and CRM apply.

Before those actions, fetch the current Go head and reconcile its sequence against
the bound snapshot. A mismatch returns a revision conflict after refresh; a timeout
returns 503. Ordinary list/history reads may show a dated stale projection with that
state. The action's receipt records upstream sequence/check time and local policy
epoch/check time. The two services do not offer a globally atomic snapshot: the
validity assertion is about these recorded checks, and a later observation triggers
invalidation. Never describe this as continuous proof that employment remains true.

Store `audit_tenant_state(tenant_id PK/FK, policy_epoch BIGINT, admission_version
BIGINT, deleting_at, updated_at)` as the common policy/deletion fence. Local policy
writers update epoch in the same transaction as their change. Admission and final
publication lock/read that row and audit generation in a consistent order; workers
recheck after external I/O. Source-policy revocation must invalidate every affected
tenant grant/projection, while direct current-policy reads prevent a delayed fan-out
from authorizing forbidden use. Elapsed time/expiry remains a direct gate even when
no event has incremented an epoch.

## Compatibility, rollout, and required checks

Proposed config under `RCH__AUDITS__*`: `ENABLE=false`, `IMPORTS_ENABLE=false`,
`REVIEW_ENABLE=false`, `REPAIR_ENABLE=false`, `CRM_ENABLE=false`,
`MAINTENANCE_ENABLE=false`, plus per-tenant allowlist. Default all new work off.
Disabling admission must not stop settlement, revocation, or deletion recovery.

Deploy Go capability support, additive Rust schema/readers, then handlers and
generated SDK/web contracts, then enable one internal tenant. Old clients retain
legacy routes and response enums. For additive DB rollback, disable writes and
keep readers/reconcilers; do not drop nonempty ledgers or pending operations.

Every implementation PR updates `backend/openapi.json`, TypeScript/Go SDKs, web
Orval models, BFF route coverage, and API inventory. Required implementation tests:
