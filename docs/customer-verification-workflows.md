# Customer verification workflows

- **Sending decisions:** the result shows the recommended action, its next step, policy, reasons, and verification time. Send-ready follows the decision instead of the raw quality score. Scores summarize rules, not delivery probabilities.
- **Clean imports:** name the lead source during CSV upload. Review duplicate counts and risk breakdowns, then build a cleanup plan and download the send-ready partition. Suggestions that change mailbox identity stay in Review. Changed results or suppressions invalidate stored export plans.
- **Ongoing health:** list workspaces link to workspace-wide scheduled checks, feedback, and source reports. Choose the age threshold and maximum addresses per run in verification settings. Each submitted address uses a credit; active suppressions are excluded. Scheduled checks produce separate jobs; use list comparisons for changes between two imports.
- **Bounce and complaint feedback:** manual entry, campaign CSV ingestion, and configured provider endpoints use existing suppression policies. Successful manual/CSV ingestion refreshes cached suppression, list, history, overview, and source views. Receiving events requires the sender integration to be configured.
- **Lead source reports:** filter by source and minimum records and download the displayed report as spreadsheet-safe CSV. Import duplicates are excluded. Verification percentages use processed records; unprocessed sources have no grade. Campaign events use their linked verification or latest tagged verification for the same tenant/mailbox. Repeated matching events across the two feedback stores are deduplicated by source, mailbox, event type, and occurrence time. Negative feedback is a share of recorded events, not a bounce rate per sent email. The report is limited to the 50 matching sources with the most invalid records.

These workflows reuse existing tenant-scoped endpoints and generated SDKs. This follow-up needs no database migration and does not enable paid schedules for customers automatically.
